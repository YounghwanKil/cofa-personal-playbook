# 연습: 검사 설비 작업 배정 도우미

이 문제와 데이터는 본선 대비를 위해 만든 합성 예시다. 실제 기출·내부 데이터·반도체 공정의 정확한 모델이 아니다. 연습 시간은 90분이다. 모델 종류와 구현 언어는 자유이며 CLI도 허용한다.

## 현장 상황

담당자는 검사 대기 작업을 두 설비에 배정한다. 기존 방식은 도착한 순서대로 가능한 설비에 넣는 것이다. 긴급 작업이 늦어지고, 설비 점검 시간을 놓치는 문제가 있다. 사용자가 파일을 넣으면 실행 가능한 배정과 지각 작업과 원인를 받고, 기준선보다 나아졌는지 확인하게 만들어라.

## 데이터와 규칙

data/jobs.csv의 시간은 기준 시점부터의 정수 분이다. 모든 작업은 비선점이며 한 설비에서 중단 없이 수행한다. start >= release, end = start + duration. 작업 ID는 유일하고 duration/weight는 양의 정수다. due는 마감 목표이며 초과할 수 있다. release/due는 0 이상의 정수다. family는 A 또는 B다.

설비 M1은 A/B를, M2는 A만 처리한다. 점검은 M1의 [40,60)이며 M2는 없다. 같은 설비의 작업은 겹치지 않고 점검과도 겹치지 않는다. 모든 구간은 [start,end)다. end=40 또는 start=60은 허용한다. 준비 시간·이동 시간·교대 제약은 없다.

목표는 총 가중 지각 Σ weight × max(0,end-due)를 줄이는 것이다. 계획 종료 시각 제한은 없다. 모든 유효 작업은 배정한다. 입력 오류가 하나라도 있으면 해당 파일 전체를 거부하고 기존 정상 결과를 보존한다.

기준선: (release, job_id) 오름차순으로 작업을 순회한다. 각 호환 설비의 이미 배정된 마지막 작업 뒤에서 release와 점검을 고려한 가장 빠른 시작을 구한다. 종료가 가장 빠른 설비를 선택하고 동점이면 설비 ID 오름차순으로 선택한다. 앞쪽 빈 공간에 삽입하지 않는다.

## 필수 요구

| ID | 수락 조건 |
|---|---|
| R1 | CSV 검증, 오류 행/이유 표시, 오류 파일 전체 거부 |
| R2 | 기준선과 개선 배정 모두 생성, 설비/시간 제약 위반 없음 |
| R3 | 동일 입력에서 총 가중 지각과 지각 작업 수 비교, 최적성 보장 여부 명시 |
| R4 | 점검 시간 변경 후 재계산, 이전 결과가 오래됐음을 구분 |
| R5 | 결과 CSV/JSON 저장과 별도 검증 명령, 새 실행에서 다시 읽기 |
| R6 | README 실행 방법, 대표 시연, 개선 이유와 한계 설명 |

개선안이 기준선보다 나쁘면 기준선을 반환하는 정책을 써도 된다. 최적해 증명은 필수가 아니다. AI API를 제품에 넣을 의무는 없다. 평가 기준은 연습용으로 요구 충족·제약 정확성·재현 가능성·설명이며 공식 배점과 무관하다.

## 독립 검증 도구

저장소의 `scripts/verify_practice.py`는 배정 알고리즘을 구현하지 않고 결과의 제약과 점수만 확인한다. Python 3 표준 라이브러리만 사용한다. 환경에 따라 `python3` 대신 `python` 명령을 쓴다. 이 연습은 헤더만 있는 빈 입력도 파일 전체 오류로 처리한다.

결과는 `[{"job_id":"J3","machine":"M2","start":10,"end":30}, ...]` 형식의 JSON 배열로 저장한다. 모든 작업이 포함되어야 한다.

```sh
python3 /자료경로/scripts/verify_practice.py /연습폴더/schedule.json --jobs /연습폴더/data/jobs.csv
python3 /자료경로/scripts/verify_practice.py /연습폴더/schedule.json --jobs /연습폴더/data/jobs.csv --maintenance 20 60
```

통과해도 입력 오류 처리·저장 보존·UI·기준선 구현까지 검증된 것은 아니다. 다른 과제에 이 검사기를 그대로 적용하지 않는다.
