# 진행자용: 55분 이후 공개

합성 연습의 정답 기준이며 실제 대회 출제 정보가 아니다.

## 기준선 계산

BRIEF의 순서·배정 규칙을 적용하면 다음과 같다.

| 작업 | 설비 | 시작 | 종료 | 가중 지각 |
|---|---|---:|---:|---:|
| J1 | M1 | 0 | 30 | 0 |
| J2 | M1 | 60 | 85 | 220 |
| J3 | M2 | 10 | 30 | 0 |
| J4 | M1 | 85 | 100 | 105 |
| J5 | M2 | 30 | 40 | 0 |
| J6 | M1 | 100 | 120 | 35 |

총 360이다. 더 나은 실행 가능 예시는 M1에 J2 0~25, J4 25~40, J6 60~80, M2에 J3 10~30, J5 30~40, J1 40~70이다. 총 가중 지각은 J1의 30뿐이므로 30이다. 이 예시가 최적이라는 주장은 하지 않는다. 모든 유효 입력에서 이만큼 개선된다는 뜻도 아니다.

## 조건 변경

55분에 M1 점검을 [20,60)으로 바꾼다. 이전 결과를 새 설정의 결과로 표시하면 실패다. 새 배정을 독립 제약 검사기로 검사한다. 오래된 결과도 설정 버전을 함께 보존할 수 있다.

## 추가 검사

- duration=0, 중복 job_id, family=C 각각 파일 전체 거부.
- 헤더만 있는 파일은 파일 전체 오류로 처리하고 기존 정상 결과를 보존.
- 기존 점검 [40,60) 기준으로 작업이 [10,40), [60,80)이면 기존 점검과 겹치지 않는다. [30,50)은 겹친다.
- 반복 실행에서 결과 재현. 난수를 쓰면 시드를 기록.
- 저장 후 프로세스를 새로 시작해 다시 읽기.
- 잘못된 파일 입력 후 기존 정상 결과 보존.

## 사용자 리허설 질문

1. J1부터 M1에 넣는 것이 왜 나쁜 결과를 만들었나?
2. 개선 알고리즘과 제약 검사기가 같은 오류를 공유하지 않게 어떻게 했나?
3. 점검 변경 전 결과를 사용자가 실수로 적용할 수 있나?
4. 실제 현장 적용 전에 어떤 제약과 데이터를 더 확인해야 하나?
5. 360→30은 어떤 입력의 어떤 지표이며 비용 절감과 어떻게 다른가?
