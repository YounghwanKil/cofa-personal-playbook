# 본선 준비 판단과 개선 근거

## 확인된 것과 모르는 것

사용자가 제공한 2026-11-07 합격 메일은 200명 결선, 실제 반도체 현장의 난제, 새로운 시각과 AI를 통한 해결 가능성을 강조한다. 제공된 행사 안내는 11월 11일 09:30~16:00 경기와 Top 20 발표를 안내한다. 구체적 과제·평가 배점·개발 환경·발표 시간·개인 도구 허용 여부는 이 자료만으로 알 수 없다.

공식 보도: https://talent.skhynix.com/hub/ko/company/story/237
위 공개 자료는 2026-11-10에 일반 대회 소개와 평가 방향을 확인했다. 세부 본선 규정의 대체물이 아니다.

“열린 문제일 수 있다”는 해석이지 자유 주제라는 확정이 아니다. 과제를 받으면 제공 레포 개선형 / 데이터 분석형 / 제약 최적화형 / 문서 검색형 / 자유 제안형 중 실제 요구를 판단한다. 여러 유형이 섞일 수 있다. 아래 연습은 출제 예측이나 실제 반도체 공정 모델이 아니다.

## 기존 흐름의 강점

예선 통과에 실제 사용했다는 사용자 피드백이 있다. 계획 승인, 파일 소유권, 고정 버전 검증, 실제 근거 기반 설명을 유지한다. 통과 원인을 이 도구 하나로 단정하지 않는다.

## 보강하는 이유

| 관찰 | 보강 | 기대 효과 |
|---|---|---|
| 기능·구현 설명 중심 | 사용자 결정·업무 손실·기준선 명시 | 해결할 문제와 가치를 연결 |
| DB/상태 중심의 질문 | 분석·최적화·검색별 검사 분기 | 과제에 맞는 검증 |
| 수동 인계가 많음 | A 기본, B 두 시점, C 마무리 | 사용자의 중계 부담 감소 |
| 검증 기준이 서술형 | 요구→입력→기대→실제 표 | 빠진 요구 발견 |
| 동시 작업을 권장 | 독립 계약이 있을 때만 선택 | 통합·환경 문제 감소 |
| 설명 자료가 풍부함 | 한 장 증거와 짧은 시연 우선 | 과장 없이 결과 전달 |

## 문제 선택법

공식 과제가 고정되어 있으면 재선택하지 않는다. 선택이 허용되면 후보를 최대 3개만 비교한다. 사용자·입력·출력·측정 지표·필요 데이터·첫 결과 예상 시간을 적고, 데이터가 없거나 시간 안에 검증할 수 없는 후보는 제외한다. 회사 전체 절감액 같은 근거 없는 숫자로 우선순위를 정하지 않는다.

하나의 사용자가 하나의 결정을 내리는 흐름을 먼저 완성한다. 새 모델 학습이나 RAG는 그 흐름에 필요한 경우만 추가한다. AI는 요구 분석·코딩·검증에 사용할 수도 있으므로 제품 안에 LLM을 넣는 것이 필수라고 가정하지 않는다. 과제가 모델 사용을 요구하면 그 요구를 따른다.

## 추가 도구 선택

기존 실행 가능한 도구를 우선한다. 브라우저 검증은 웹 UI일 때, 데이터 점검은 표 데이터일 때, 제약 검사기는 배정 문제일 때 쓴다. 모두 사전 리허설로 실제 연결을 확인한다. 특정 공급자·모델·외부 호스팅을 필수로 만들지 않는다. 새로운 다중 모델 라우터를 대회 전날 전체 흐름에 삽입하지 않는다.

## 오늘 90분 리허설

연습 데이터는 합성 데이터다. 15분 분석·계획, 40분 구현, 20분 검증·조건 변경, 15분 설명·재실행을 연습한다. 처음에는 진행자용 REVIEWER.md를 읽지 않는다. 도구 준비나 설치에 10분 넘게 막히면 익숙한 환경으로 줄인다. 완료 후 실제로 막힌 한두 부분만 고친다.
