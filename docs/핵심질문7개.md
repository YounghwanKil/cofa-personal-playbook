# 과거 기출 유형 기반 예상 질문 7개

과거 기출 유형을 바탕으로 구현 선택·데이터 흐름·조건 변경·검증·실패 대응을 연습하도록 구성한 예상 질문입니다. 현재 프로젝트의 실제 코드와 실행 결과에 맞춰 답변을 준비하세요.

1. 왜 최적해 알고리즘을 사용하지 않고 휴리스틱 알고리즘으로 결과를 뽑았는가?
2. 백엔드에서 사용한 모듈 구조는 무엇인가? 데이터 흐름을 알려 달라.
3. 운영진이 갑자기 최대 정원이나 소요 시간 등의 조건을 바꾸면 어떻게 되는가?
4. 검증하면서 발견하고 고친 것은 무엇인가?
5. 동작하는 흐름을 설명하라. 데이터는 어떻게 흐르는가?
6. 추가적으로 가정한 것은 무엇인가? “검증을 통과하지 못한 데이터는 쓰지 말라”는 요구를 위해 추가로 구현하거나 구현하지 않은 것은 무엇인가?
7. 한 번 요청하면 계산이 끝날 때까지 기다리게 구현했는데, 중간에 계산 오류나 DB 변경 등의 문제가 생기면 어떻게 되는가?

## 이번 구현에서 준비할 근거

| 질문 | 실제 프로젝트에서 찾아 둘 근거 |
|---|---|
| 1 | 목표 함수·제약·입력 크기, 선택 방법, 검토한 대안, 실행 결과, 최적성 보장 여부. 휴리스틱을 무조건 선택하지 않는다. |
| 2 | 실제 외부 패키지와 내부 모듈을 구분하고 각 역할·호출 관계를 확인한다. |
| 3 | 조건 저장 위치, 변경 적용 시점, 진행 중 작업의 입력 일관성, 기존 결과 무효화·재계산 정책을 확인한다. |
| 4 | 실제 실패 입력 → 기대/관찰 결과 → 원인 → 코드 수정 → 재검사 결과를 남긴다. 발견하지 않은 버그를 꾸며내지 않는다. |
| 5 | 작은 입력 한 건이 화면/요청 → 검증 → 조회 → 계산 → 저장 → 응답/표시로 바뀌는 과정을 실제 함수로 설명한다. 해당하지 않는 단계는 제외한다. |
| 6 | 공식 요구와 자체 가정을 분리한다. 검증 실패 데이터의 계산·저장·재조회·재사용 경로를 확인한다. 일부 허용 여부는 요구에 따라 결정한다. |
| 7 | 예외·타임아웃·부분 저장·재시도·중복 계산·동시 DB 변경에 대한 현재 동작과 미구현 한계를 구분한다. 비동기 문법만으로 작업 복구를 보장한다고 말하지 않는다. |

```text
특히 검증 중 실제 수정한 사례와 검증 실패 데이터의 사용 차단 경로를 확인해라.

```

배포 방식에 관한 예상 질문도 함께 준비한다. 실제 실행 환경·배포 명령·저장 위치·확인 근거로 답하며, 설정 파일만으로 배포 성공을 주장하지 않는다.
