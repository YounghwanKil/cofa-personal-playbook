## 높음

**H1. B의 격리 사본과 기록 파일 경로가 연결되지 않음 (실행 불가)**
- FINALS §4는 "B를 격리된 사본에서 열라"고 합니다. START_HERE §2는 "세션은 같은 과제 루트에서 연다"고 해서 서로 모순됩니다.
- 격리 사본이 git worktree이거나 커밋 기준 사본이면 미커밋 PLAN과 `.work/HANDOFF.md`가 사본에 없습니다. B가 "PLAN과 HANDOFF를 읽고"를 수행할 수 없습니다.
- B가 `.work/REVIEW.md`를 사본 안에 쓰면 A가 읽을 수 없습니다. "고정 사본을 변경하지 않는다"는 규칙도 깨집니다.
- 사본에 의존성(venv, node_modules)이나 데이터가 없어 실행이 실패할 수 있습니다.
- **최소 수정** (FINALS_B 첫 줄):
  > 준비 자료 [경로], 과제 루트 [경로], 고정 검토 사본 [경로]. PLAN·HANDOFF는 과제 루트에서 읽고, 실행은 사본에서만 하며, 결과는 과제 루트의 .work/REVIEW.md에만 쓴다.

  START_HERE §2에는 "B는 실행만 격리 사본에서 한다"는 예외를 한 줄 추가합니다.

**H2. 본선 당일 받을 버전이 보장되지 않음**
- FINALS §2에 "로컬 개선본은 GitHub main과 다를 수 있다"고 되어 있습니다.
- 그런데 README의 받기 절차는 `git clone --depth 1`(main)뿐입니다. 본선 추가분이 push되지 않았다면 당일에 FINALS.md 없이 받게 됩니다.
- `git log -1`은 미커밋 수정을 보여주지 않습니다.
- **최소 수정**: 오늘 commit/push한 뒤 해시를 기록합니다. 당일에는 다음을 확인합니다.
  > `git -C .cofa-playbook rev-parse --short HEAD`가 기록한 해시와 같고 `git -C .cofa-playbook status --short`가 비어 있는지 확인한다.

## 낮음

**L1. REVIEWER 경계 사례의 기준 점검 시간 불명확**
- "[10,40)은 겹치지 않는다"는 [40,60) 기준에서만 참입니다. 바로 위 조건 변경 후 기준인 [20,60)에서는 겹칩니다.
- **수정**: "(기존 [40,60) 기준)"을 명시합니다.
- 선택 사항으로, 변경 후 기대값을 추가하면 진행자가 대조하기 쉽습니다. 제가 손으로 계산한 값은 다음과 같습니다.
  - [20,60) 기준선: J1 M2 0~30, J2 M1 60~85, J3 M2 30~50, J4 M1 85~100, J5 M2 50~60, J6 M1 100~120, 총 **410**
  - 개선 예시: M1에서 J4 60~75, J2 75~100, J6 100~120 순서로 두면 M1이 345입니다. M2를 J3, J5, J1 순서로 두면 30입니다. 총 **375**입니다.

**L2. BRIEF의 JSON 예시가 정답 힌트를 노출**
- 예시 `{"job_id":"J1","machine":"M2","start":40,"end":70}`은 개선해의 핵심 수입니다. "처음에는 REVIEWER를 읽지 않는다"는 취지와 어긋납니다.
- **수정**: 기준선의 행인 `{"job_id":"J3","machine":"M2","start":10,"end":30}`으로 교체합니다.

**L3. 검증기 사용성**
- 기본 `--jobs`는 자료 저장소의 원본을 봅니다. 연습 폴더 사본을 검사하도록 BRIEF 명령에 `--jobs /연습폴더/data/jobs.csv`를 넣습니다.
- BOM이 있는 CSV는 `INVALID: 'job_id'`라는 모호한 오류를 냅니다. `encoding='utf-8-sig'`로 바꾸고, `read_text(encoding='utf-8')`로 인코딩을 명시합니다.
- 헤더만 있는 파일은 검증기가 항상 거부합니다. 사용자가 "빈 결과" 정책을 고르면 검증기와 충돌하므로 BRIEF에 이 동작을 명시합니다.
- Windows에서는 `python3` 대신 `python`일 수 있다는 점을 한 줄 추가합니다.

**L4. FINALS_A 프롬프트 누락**
- "정본이 없으면 PLAN.md 작성"만 있고, 정본이 있을 때의 동작이 없습니다. "있으면 그 정본을 갱신"을 추가합니다.
- 고정 버전을 만들 때 START_HERE §4의 HANDOFF 기록 항목이 빠져 있습니다. 사용자가 B에 넘길 경로를 얻을 수 있도록 다음을 추가합니다.
  > 검토 ID·기준 커밋·격리 경로·재현 명령을 HANDOFF에 기록

**L5. FINALS §3의 메타 문장**
- "준비 자료 개선 작업에 별도 승인을 요구하는 규칙은 아니다"는 준비 대화의 흔적으로 보입니다. 당일 독자에게는 혼란만 주므로 삭제합니다.

**L6. FINALS §6의 "README" 지칭 모호**
- 플레이북 README와 혼동될 수 있으므로 "제품 README의 수동 실행 절차"로 바꿉니다.

**L7. FINALS_STRATEGY의 공식 URL 출처 표기**
- "앞선 조사에서 확인"에는 확인 일자와 확인 내용이 없습니다. 저는 그 내용을 검증하지 않았으며 추측하지 않겠습니다.
- **수정**: "(확인일 YYYY-MM-DD, 일반 소개만 확인)" 정도를 붙입니다.
