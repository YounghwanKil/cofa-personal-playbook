# 버스가 아닌 주제로 전이하는 사전 연습

아래는 직접 만든 가상 문제이며 공개 기출·오늘의 출제 예측이 아니다. 특정 앱을 크게 만들기보다 작은 입력의 결과와 선택·실패 조건을 설명하는 연습에 쓴다.

## 1. 설비 작업 배정

**가상 요구:** 작업별 처리 시간·가능 설비·마감 시간이 있다. 각 설비는 한 번에 하나만 처리하고, 모든 작업은 최대 한 설비에 배정한다. 미배정 작업 수를 먼저 줄이고, 그다음 총 지연을 줄인다. 관리자 처리 시간 변경을 지원해야 한다.

**작은 입력:** 설비 M1 하나, 시각 0 시작. 작업 A는 처리 3·마감 4, B는 처리 2·마감 3. 둘 다 M1 가능, 선점·준비 시간 없음.

- A→B: 완료 3·5, 지연 0·2, 합계 2.
- B→A: 완료 2·5, 지연 0·1, 합계 1.

두 경우 모두 설비 중복과 시간 겹침은 없다. 이는 두 작업의 순서 비교이며, 일반 규모에서 마감순이 항상 최적이라는 증거는 아니다.

**구현 순서:** 입력 검증→단순 배정 기준선→결과 제약 검증→표시→설정 변경 시 새 계산. 긴 입력·시간 상한이 실제 요구되면 작업 상태를 추가한다.

**설명할 질문:** 왜 그 순서인가? 해가 없으면 어떤 상태인가? 마감 준수와 처리량 중 무엇이 우선인가? 계산 중 설비가 멈추면 기존 결과를 적용할 수 있나? 이미 시작한 작업을 재배정 가능한가?

버스의 “차량 정원·정차 시간”은 이 예시의 “설비 용량·처리 시간”으로 바뀐다. 입력 버전과 오래된 결과의 적용 문제는 공통이다.

## 2. 재고 부족 판정

**가상 요구:** 품목별 가용 재고를 `현재 재고 - 확정 예약량`으로 계산한다. 가용 재고가 안전재고보다 작으면 경고하고, 같으면 경고하지 않는다. 결측값은 확인 필요로 표시한다.

**작은 입력:** X의 현재 재고 12, 확정 예약 5, 안전재고 7이면 가용 재고 7로 정상. 예약 6이면 가용 재고 6으로 경고. 예약량 결측은 0으로 채우지 않고 확인 필요.

**구현 순서:** 행·식별자 의미 확인→계산 함수→경계값 검사→원본과 독립 집계 비교→표/필터/요구된 내보내기.

**설명할 질문:** 왜 ML을 안 썼나? 예약 테이블에 같은 품목이 여러 행이면 어떻게 합치나? 경고 결과가 나온 뒤 다른 주문이 들어오면? 재고 차감은 판정과 같은 트랜잭션인가? 판정만 하는 도구와 실제 주문 확정 도구의 차이는?

여기에는 최적화 솔버가 필요하지 않을 수 있다. 미리 휴리스틱 구조를 정해두면 오히려 문제에 맞지 않는다.

## 3. 품질 검사 데이터 분석

**가상 요구:** 검사 ID별로 최초 검사만 집계해 불량률을 계산한다. 재검사는 별도 표시한다. 검사 시각이 같으면 기록 ID로 동점을 해소한다. 임계값과 같은 비율은 경고하지 않는다.

**작은 입력:** 최초 검사 대상 A·B·C 중 A만 불량이면 1/3. A의 재검사 합격 한 건을 원래 분모·분자에 추가하지 않는다. 임계값 1/3과 정확히 같다면 이 가상 규칙에서는 비경고다. 화면 반올림 값으로 판정하지 않는다.

**구현 순서:** 검사·재검사·시간 단위 확인→원본 보존→정렬/중복 정책→집계→반례·조인 전후 합계 확인→결과 표시.

**설명할 질문:** 분모는 제품 수인가 검사 수인가? 최신 검사가 아니라 최초를 택한 근거는? 결측 판정은 정상인가? 과거 기록이 수정되면 리포트를 다시 만들 수 있나? 샘플에서 확인한 결과를 전체 데이터에도 보장하나?

## 각 문제에서 5분 리허설

1. 구현 목적과 입력→최종 결과를 1분 안에 말한다.
2. 사용 모듈·실행/배포 위치를 파일 근거로 말한다.
3. 선택한 방법과 검토한 대안 하나를 비교한다.
4. 설정 변경·중간 실패 중 하나의 구체적 상황을 따라간다.
5. 현재 한계와 가장 먼저 보완할 것을 한 가지씩 말한다.

모든 문제에 같은 답안을 외우는 대신, 같은 질문 틀을 서로 다른 실제 코드와 업무 규칙에 연결하는 것이 목표다.
