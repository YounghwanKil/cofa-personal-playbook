# 실제 프로젝트에서 설명 근거를 뽑는 요청문

전체 운영안·입장 첫 프롬프트는 [초기 세팅과 에이전트 전략](07-입장직후세팅과에이전트전략.md)에 있다. 아래는 개발 중 필요한 단계에만 사용한다.

## 모듈·데이터 흐름 확인

```text
현재 코드에서 실제 사용하는 외부 패키지와 내부 모듈을 구분해라.
의존성 파일의 선언과 실제 import·호출 여부를 대조해라.
각 모듈의 역할, 입력·출력, 실제 호출 파일:함수를 표로 써라.
사용자 행동 하나를 골라 화면→API→검증→조회→계산→저장→표시를 추적해라.
존재하지 않는 API·DB·큐를 일반적인 구조라는 이유로 채우지 마라.
```

## 알고리즘 선택 확인

```text
실제 계산 함수에서 목적함수·하드 제약·탐색 순서·종료 조건을 추출해라.
문제의 어떤 조건 때문에 이 방식이 필요한지 당시 결정 기록과 대조해라.
대안은 최대 2개만 비교하고 측정한 사실과 사후 추론을 분리해라.
작은 손계산 사례와 단순 기준선으로 검증할 방법을 제안하고,
허용된 현재 작업 범위의 검사를 실행해 실제 결과와 한계를 남겨라.
```

## 설정 변경·실패 시나리오 확인

```text
현재 구현에서 1) 계산 중 설정 수정 2) 계산 중 원본 변경
3) 요청 재전송 4) 프로세스 강제 종료 5) 결과 저장 실패가 나면
무슨 상태·데이터가 남는지 코드 근거로 설명해라.
현재 보장, 실제 결함, 미검증, 개선안을 구분해라.
필수 요구를 깨는 가장 큰 위험부터 재현하고 최소 수정해라.
추가 워커·캐시·큐를 근거 없이 일괄 도입하지 마라.
```

## 배포 확인

```text
실제 실행 환경과 배포 기록을 확인해라.
호스팅 위치·서버·빌드/시작 명령·포트·DB 위치·환경변수 이름·접근 URL을 정리해라.
환경변수 값이나 비밀은 출력하지 마라.
배포 설정만 있는 상태와 실제 배포/접근 확인을 구분해라.
현재 권한과 제공 환경 안에서 대표 입력→저장→재조회와 오류 응답을 확인해라.
실행 안 한 항목은 미검증으로 남겨라.
```

## 설명 초안 검토

```text
PROJECT_DEFENSE.md를 실제 코드·의존성·실행 기록과 대조해라.
없는 모듈, 사용하지 않은 라이브러리, 배포하지 않은 서비스,
측정하지 않은 성능, 구현하지 않은 동시성/복구 보장을 찾아라.
문장을 사실/가정/미검증/개선안으로 고치고 파일:함수 근거를 붙여라.
새로운 선택 이유를 당시 판단인 것처럼 만들지 마라.
```

## 답을 숨긴 사전 연습

```text
현재 프로젝트를 바탕으로 후속 질문 5개만 먼저 제시해라.
배포·모듈·데이터 흐름 중 2개, 선택·변경 대응·실패 중 3개를 골라라.
내가 답할 때까지 모범답안과 힌트를 보여주지 마라.
내 답을 받은 뒤 실제 코드와 다른 주장, 빠진 한계, 근거 부족을 짚고
다른 사례의 꼬리 질문 1개로 다시 확인해라.
```
