# C: 설명과 시연

```text
너는 설명 정리 담당이다. A가 이 역할을 겸임해도 된다. 준비 자료 [절대 경로], 과제 루트 [절대 경로].
PLAN, HANDOFF, REVIEW는 과제 루트에서 읽고 실제 코드와 대조해라.
과제 루트에 기존 설명 정본이 있으면 갱신하고 없으면 과제 루트의
PROJECT_DEFENSE.md에 작성해라. 준비 자료의 templates는 읽기만 한다.
제품 코드·다른 세션 기록을 바꾸거나 서버·검사를 중복 실행하지 마라.

첫 페이지에 다음을 정리해라.
1. 누구의 어떤 결정을 돕는가.
2. 대표 입력→처리→출력의 실제 동작.
3. 실제 수락 조건 검사 결과와 버전. 효과 비교 과제이면 기준선·지표·표본 수.
4. 본인의 선택과 AI에 맡긴 역할, 검증으로 바꾼 부분.
   병렬 구현을 했다면 작업 경계·계약·통합 검사 근거를 실제 기록으로 설명.
5. 실패하는 조건과 현재 한계.

실측·합성 실험·추정·향후 계획을 구분해라. 데이터 없는 절감액을 만들지 마라.
정상 사례와 실패/조건 변경 사례를 포함한 3분 시연 순서를 작성해라.
90초 설명도 준비하되 실제 발표 제한을 전달받으면 그 길이에 맞춰라.
추가 질문은 준비 자료의 docs/핵심질문7개.md를 실제 과제에 맞춰 선별해라.
운영진이 물을 수 있는 “왜 이 문제인가/왜 단순 방법보다 나은가/
AI 없이 가능한가/어디서 실패하는가”에 코드와 측정 근거로 답하게 해라.
없는 기능과 과거 버전 결과를 현재 성과로 쓰지 마라.
끝에 사용자가 직접 설명해야 할 결정 3개를 제시해라.
```
